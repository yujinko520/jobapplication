# 02. 시간복잡도 — 문제 보고 알고리즘 고르는 법

알고리즘 문제에서 **가장 먼저 봐야 할 건 제한 조건(N의 크기)** 입니다.
N만 보면 어떤 알고리즘을 써야 하는지 거의 정해집니다. 이게 코테의 핵심 스킬입니다.

## 1. 기준선: 1초에 약 1억 번

채점 서버는 대략 **1초에 1억(10^8) 번 정도 연산**합니다.
Python은 C보다 느려서 **실제로는 1초에 1000만(10^7) 번** 정도로 잡는 게 안전합니다.
(그래서 대부분의 코테는 Python에 시간 제한을 넉넉히 줍니다)

## 2. N 보고 알고리즘 고르기 ★ 이 표를 외우세요

| N의 크기 | 허용 복잡도 | 쓸 수 있는 알고리즘 |
|---|---|---|
| N ≤ 10 | O(N!) | 완전탐색, 순열 (`permutations`) |
| N ≤ 20 | O(2^N) | 부분집합 전체 탐색, 비트마스크 |
| N ≤ 100 | O(N³) | 3중 반복문, 플로이드-워셜 |
| N ≤ 1,000 | O(N²) | 2중 반복문, 삽입/선택 정렬, 기본 DP |
| N ≤ 100,000 | O(N log N) | **정렬, 이분탐색, 힙, 우선순위 큐** ← 제일 흔함 |
| N ≤ 1,000,000 | O(N) | 한 번 훑기, 투포인터, 해시, BFS/DFS |
| N ≥ 10,000,000 | O(log N) / O(1) | 수학 공식, 이분탐색만 |

**사용법 예시**

> "N은 100,000 이하입니다" → O(N²)은 100억이라 불가능 → **정렬이나 이분탐색 계열이구나**

> "N은 20 이하입니다" → 이렇게 작다는 건 **일부러 완전탐색 하라는 뜻**

N이 작으면 "어려운 알고리즘을 쓰라"가 아니라 **"다 해봐도 된다"** 는 힌트입니다.
초보자가 제일 많이 놓치는 부분이에요.

## 3. 복잡도 읽는 법 (간단하게)

세는 건 **"가장 안쪽 줄이 몇 번 실행되는가"** 입니다.

```python
for i in range(n):          # n번
    for j in range(n):      #   × n번
        x += 1              #     → n² 번  ⇒ O(n²)
```

```python
while n > 0:
    n //= 2                 # 절반씩 줄어듦 ⇒ O(log n)
```

규칙 3가지만 알면 됩니다:

1. **상수는 버린다**: O(3n) → O(n), O(n/2) → O(n)
2. **가장 큰 항만 남긴다**: O(n² + n) → O(n²)
3. **중첩은 곱한다**: n번 루프 안에 정렬(n log n) → O(n² log n)

## 4. Python 연산별 복잡도 — 시간초과의 진짜 원인

| 연산 | 복잡도 | 비고 |
|---|---|---|
| `arr[i]` | O(1) | |
| `arr.append(x)` / `arr.pop()` | O(1) | |
| `arr.pop(0)` / `arr.insert(0,x)` | **O(n)** | ⚠️ deque 쓰세요 |
| `x in list` | **O(n)** | ⚠️ set이면 O(1) |
| `x in set` / `x in dict` | O(1) | |
| `arr.sort()` | O(n log n) | |
| `min()` / `max()` / `sum()` | O(n) | ⚠️ 루프 안에서 부르면 O(n²) |
| `''.join(list)` | O(n) | |
| 문자열 `s += t` 반복 | **O(n²)** | ⚠️ |
| `heappush` / `heappop` | O(log n) | |
| 슬라이싱 `arr[a:b]` | O(b-a) | ⚠️ 루프 안 슬라이싱 주의 |

**시간초과가 나면 이 표를 먼저 보세요.** 알고리즘이 틀린 게 아니라
자료구조를 잘못 골라서인 경우가 절반 이상입니다.

```python
# ❌ O(n²) — 루프마다 리스트 전체를 훑음
for x in arr:
    if x in seen_list: ...

# ✅ O(n)
seen = set(seen_list)
for x in arr:
    if x in seen: ...
```

```python
# ❌ O(n²) — 매 반복마다 min()이 전체를 훑음
for i in range(n):
    m = min(arr)

# ✅ O(n)
m = min(arr)
for i in range(n):
    ...
```

## 5. 공간복잡도도 가끔 봅니다

메모리 제한은 보통 **256MB**. Python 정수 리스트는 원소당 약 28~36바이트라
넉넉잡아 **원소 100만 개 ≈ 40MB** 정도로 생각하면 됩니다.

- `[0] * 10_000_000` → 위험
- 2차원 `1000 × 1000` → 100만 칸, 괜찮음
- 방문 배열은 `set` 대신 리스트가 메모리는 더 유리할 때가 많음

## 6. 연습

제한 조건을 보고 알고리즘을 추측해 보세요. (답은 아래)

1. `1 ≤ N ≤ 1,000,000`, 배열에서 두 수의 합이 K인 쌍 찾기
2. `1 ≤ N ≤ 15`, N개 도시를 모두 방문하는 최소 비용
3. `1 ≤ N ≤ 100,000`, 정렬된 배열에서 특정 값 찾기
4. `1 ≤ N ≤ 500`, 모든 도시 쌍 사이의 최단거리

<details>
<summary>답</summary>

1. O(N) — 해시(set) 또는 정렬 후 투포인터
2. O(2^N · N) — 비트마스크 DP (외판원 순회). N=15니까 지수 시간 허용
3. O(log N) — 이분탐색
4. O(N³) = 1.25억 — 플로이드-워셜 (파이썬은 빠듯하지만 의도된 풀이)

</details>
