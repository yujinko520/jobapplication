## §3. 증상 → 원인 역색인 (막혔을 때 여기부터)

### "정답입니다"가 안 뜨는데 에러도 없다

| 증상 | 1순위 의심 |
|---|---|
| 출력이 통째로 이상하다 | **타입 불일치** — `1 in ('1','4','7')` 은 `False`. 에러 없이 조용히 틀림 |
| 결과가 **1 적다 / 마지막이 빠졌다** | **`range` 끝값 `+1`** |
| 일부 케이스만 틀린다 | **초기 상태 / 첫 원소 / 마지막 원소** (§1의 3·5번) |
| 조건을 처리했는데 반영이 안 된다 | `answer = ...` 가 **아래에서 덮어써졌다** → 그 자리에서 `return` |
| 빈 입력에서만 틀린다 | `arr[0]`을 초기값으로 썼다 → `0`에서 시작하도록 고친다 |

### 에러 메시지

| 메시지 | 뜻 |
|---|---|
| `'int' object is not iterable` / `has no len()` / `is not subscriptable` | **정수를 목록처럼 취급**했다. `for i in h:` → `for i in range(h):` |
| `list indices must be integers, not str` | `for x in 리스트` 는 **원소**를 준다. 인덱스가 필요하면 `enumerate` |
| `unhashable type: 'list'` | 리스트를 dict 키/set 원소로 썼다 → **튜플**로 |
| `TypeError: 'dict' object is not callable` | `d(x)` → `d[x]` |
| `KeyError: 0` | 집계용 dict를 **원본인 줄 알고 읽었다** (이름을 구분하라) |
| `UnboundLocalError` | 루프 안에서만 만들어지는 변수를 **루프 밖에서** 썼다 → 그 자리에서 `return` |

### "시간 초과" / 효율성 테스트 실패 — **이 순서로 본다**

1. **무한루프가 아닌가?** ← 10/5 기준 내 1순위 원인
   - **반복 중인 리스트에 `append`/`remove`** 했다 (에러 없이 멈춘 것처럼 보인다)
   - `while` 조건이 변하지 않는다
2. 바깥 루프는 보통 필수다. **안쪽을 줄여야 한다** → `√n` / dict / 정렬
3. 같은 계산을 반복하나 → 미리 계산해두기
4. **완전탐색 전에 "변수를 줄일 수 있나?"를 묻는다** (카펫: O(N²) → O(N))

## §4. 외워서 치는 코드

> 각 블록 제목 옆 `[0/2]` = **빈 화면 재현 성공 횟수**. `[2/2]`가 되면 그날 **블록을 지우고 §8로** 옮긴다.
> (BFS 템플릿은 예외 — 외워도 10/24까지 남긴다)

### ★★ `is_prime` — `return True`의 위치가 전부다  `[0/2]`

```python
def is_prime(n):
    if n < 2:                # 0, 1은 소수가 아니다
        return False
    j = 2
    while j * j <= n:        # √n 까지만
        if n % j == 0:
            return False     # 하나라도 나눠지면 즉시
        j += 1
    return True              # ★★ 루프 '밖'
```

`return True`를 `while` 안에 넣으면 1~200 중 **54개 오판** (9, 15, 25를 소수라고 함).

### ★★ 약수 개수 — 같은 √n, 다른 목적  `[0/2]`

```python
cnt, j = 0, 1
while j * j <= i:
    if i % j == 0:
        cnt += 1 if j * j == i else 2    # 제곱수면 1개, 아니면 j와 i//j
    j += 1
```

> **"하나라도 있나" = 즉시 `return` / "몇 개인가" = 끝까지 센다.**

### ★ "모든 것에 대해 참" 검사 — 두 결론의 위치가 다르다  `[0/2]`

```python
ok = True
for ...:
    if 안됨:
        ok = False; break    # 실패는 루프 '안'에서 즉시
if ok:                       # 성공은 루프 '밖'에서 판정
    ...
```

### ★ 그리디 — 처리된 범위를 변수로  `[0/2]`

```python
cnt, end = 0, 0
for s in section:
    if s > end:
        cnt += 1
        end = s + m - 1      # ★ end 기준이 아니라 s 기준
```

### ★ 슬라이딩 윈도우 — 구간 개수 `n - k + 1`  `[0/2]`

```python
for i in range(n - k + 1):   # ★ +1
    d = {}                   # ★ 구간마다 독립이면 루프 '안'에서 초기화
    for j in range(i, i + k):
        d[arr[j]] = d.get(arr[j], 0) + 1
```

`n < k` 면 빈 범위 → 자동으로 0건. 예외 처리 불필요.

### 격자 4방향 (BFS·시뮬레이션 공통)  `[0/2]`

```python
dx, dy = [-1, 1, 0, 0], [0, 0, -1, 1]
for k in range(4):
    nx, ny = x + dx[k], y + dy[k]
    if 0 <= nx < h and 0 <= ny < w:
        ...
```

**검사 먼저, 이동 나중**: 임시 좌표 `nx, ny = x, y` + `ok` 플래그로 검사하고, `if ok:` 일 때만 확정.

### 자주 쓰는 한 줄  `[0/2]`

```python
d = dict(zip(keys, values))        # 두 리스트를 dict로
d[k] = d.get(k, 0) + 1             # 개수 세기 (.get은 '반환'만, 저장 안 함)

best = max(best, 이번값)            # 누적 최댓값
```

## §5. N 보고 알고리즘 고르기

| N | 허용 복잡도 | 알고리즘 |
|---|---|---|
| ≤ 10 | O(N!) | 순열 완전탐색 (`permutations`) |
| ≤ 20 | O(2^N) | 부분집합, 백트래킹 |
| ≤ 100 | O(N³) | 3중 루프 |
| ≤ 1,000 | O(N²) | 2중 루프, 기본 DP |
| ≤ 100,000 | O(N log N) | **정렬, 이분탐색, 힙** |
| ≤ 1,000,000 | O(N) | 투포인터, 해시, **BFS/DFS** |
| ≥ 10,000,000 | O(log N) | 수학, 이분탐색 |

> **N이 작으면 "다 해봐도 된다"는 힌트다.** 어려운 알고리즘을 찾지 말 것.

| itertools | 언제 |
|---|---|
| `combinations(arr, k)` | 순서 **무관** |
| `permutations(arr, k)` | 순서 **중요** |
| `product(arr, repeat=k)` | 중복 허용 |

- **값이 아니라 자리로 뽑는다** → `'011'` 처럼 중복 값이 있으면 결과도 중복 → `set`으로 받기
- **제너레이터**다. `len()` 안 되고, 한 번만 순회 가능
- 뽑는 개수가 **입력에 따라 변하면** itertools로 안 된다 → 재귀(백트래킹)
