# 03. 시험 당일 전략

> 📌 이 문서는 **전략**이다. 내가 실제로 틀린 것·외울 코드는
> **[05-exam-final-check.md](05-exam-final-check.md)** — 시험장에는 그 파일 한 장만 가지고 가면 된다.

실력만큼 중요한 게 **시험 운영**입니다. 풀 수 있는 문제를 시간 배분 실패로 놓치는 일이 정말 많아요.

## 1. 시험 직전 (D-1)

- **새 알고리즘 공부 금지.** 안 하던 걸 전날 해봐야 불안만 커집니다
- 이미 푼 문제 중 **BFS/DFS 2개, DP 1개**만 다시 쳐보기 (손 풀기)
- [프로그래머스 반환 형식](00-getting-started.md) 다시 확인 (`return`, 리스트 타입)
- 일찍 자기. 알고리즘은 컨디션 영향이 매우 큽니다

## 2. 시작 직후 5분 — 전체 훑기 ★

절대 1번부터 바로 풀지 마세요.

1. **모든 문제를 훑고** 난이도를 A(쉬움)/B(풀 만함)/C(어려움)로 분류
2. **A → B → C 순서로** 풉니다
3. 각 문제의 **제한 조건(N)** 을 먼저 확인 → 알고리즘 후보 메모

배점이 같다면 **쉬운 문제부터**가 무조건 이득입니다.

## 4. 막혔을 때 체크리스트

### 아이디어가 안 떠오를 때
- 제한 조건(N) 다시 보기 → 완전탐색 가능한 크기인가?
- **입출력 예제를 손으로** 풀어보기 → 규칙이 보임
- "이게 어떤 유형이지?" 15개 유형 중 하나에 대입해 보기
- 작은 케이스(n=1, n=2)부터 손으로 → 점화식이 보이기도 함

### "실패"가 나올 때 — 엣지 케이스 목록
- [ ] N = 1, N = 0 인 경우
- [ ] 원소가 전부 같은 경우
- [ ] 음수, 0이 포함된 경우
- [ ] 최댓값/최솟값 경계 (int 범위, 배열 끝)
- [ ] 답이 없을 때 반환해야 하는 값 (-1? 0? 빈 리스트?)
- [ ] **반환 타입** (리스트여야 하는데 튜플 반환하지 않았나)

### 시간 초과 / 효율성 테스트 실패일 때
1. 리스트에 `in` 쓰고 있나 → `set`으로
2. `list.pop(0)` 쓰고 있나 → `deque.popleft()`
3. 반복문 안에서 `min/max/sum/sort/슬라이싱` 호출하나
4. 문자열 `+=` 반복하나 → `''.join()`
5. 그래도 안 되면 → 복잡도 자체를 잘못 잡은 것. 알고리즘을 바꿔야 함

> **정확성은 통과 / 효율성만 실패** = 답은 맞는데 느리다는 뜻입니다.
> 완전탐색으로 짰다면 정렬·해시·이분탐색으로 갈아타야 합니다.

### 런타임 에러가 나올 때
- 재귀 깊이 (`sys.setrecursionlimit(10**6)`)
- 인덱스 범위 (`n` vs `n+1`, 1-indexed vs 0-indexed)
- 빈 리스트에 `pop()` / `max()` / `min()`
- 0으로 나누기

## 5. 부분 점수 전략

프로그래머스는 **테스트케이스별 부분 점수**를 줍니다.

- 최적해를 모르겠으면 **일단 완전탐색이라도 제출**하세요. 정확성 테스트는 통과합니다
- 0점보다 30점이 훨씬 낫습니다
- 시간이 남으면 그때 최적화

**빈칸으로 내는 것만은 피하세요.**
