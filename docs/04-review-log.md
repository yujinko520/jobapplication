## 🔴 반복 실수 (같은 걸 2번 이상 틀린 것 — 시험 전날 필독)

### ① `return arr.sort()` → `None` 반환  [9/29 하루에 2번]

```python
return answer.sort()      # ❌ None이 나간다. 프로그래머스는 "실패"만 뜨고 이유를 안 알려줌
return answer             # ✅
return sorted(answer)     # ✅ 정렬이 필요하면 이쪽
```

**원인이 된 Python 규칙**: *원본을 바꾸는 메서드는 값을 돌려주지 않는다.*
`.sort()` `.append()` `.reverse()` `.add()` `.update()` 전부 `None` 반환.

```python
arr = [1,2].append(3)     # ❌ arr == None
arr = sorted([2,1])       # ✅ 새 리스트를 돌려주는 함수만 대입 가능
```

**예방 습관**: `return` 을 칠 때마다 "이게 **값을 돌려주는** 표현인가?" 한 번 확인.

### ② 예제 3개 통과 ≠ 정답  [9/29 최소직사각형 · 9/30 덧칠하기 · 9/30 키패드 누르기 — **3회**]

예제만 보고 규칙을 일반화했다가 반례가 나온 사례.

- 세운 가설: "명함 2n개의 변을 **전부 한 줄로** 정렬해서 1번째 × (n+1)번째"
- 공식 예제 3개 **전부 통과** → 맞는 줄 알았음
- 무작위 1000회 검증 시 **584회 불일치**

```
명함: [100,90], [3,2], [3,2], [3,2]
전부 정렬: [100, 90, 3, 3, 3, 2, 2, 2]
가설 = 100 × 3 = 300     정답 = 100 × 90 = 9000
```

**왜 틀렸나**: 전부 섞어 정렬하면 `100`과 `90`이 **같은 명함**이라는 관계가 끊어진다.
비교는 그룹 전체가 아니라 **각 원소 내부(자기 두 값끼리)** 에서 해야 했다.

**예방 습관** — 제출 전 반례 만들기 (30초면 된다):
- 원소가 **1개**일 때
- 값이 **전부 같을** 때
- **하나만 극단적으로 큰** 경우 ← 이번 반례가 이 유형
- 0, 음수, 최댓값 경계

> 예제는 보통 3개, 채점 케이스는 수십 개다. 예제 통과는 출발선이지 결승선이 아니다.

### ③ 정수 `1` ≠ 문자열 `'1'`  [9/30 키패드 누르기]

```python
numbers = [1, 3, 4]          # int 리스트
1 in ('1', '4', '7')         # False ★ 에러도 안 나고 조용히 틀림
1 == '1'                     # False
```

`if number in ('1','4','7')` 이라고 써서 **모든 분기가 else로 떨어졌다.**
예외가 안 나니 원인을 못 찾고 출력만 통째로 이상해진다.

**예방**: 문제를 읽을 때 입출력 예제의 **대괄호 안에 따옴표가 있는지** 확인한다.

| 예제 표기 | 타입 |
|---|---|
| `[1, 3, 4]` | int |
| `["1", "3"]`, `"aabb"` | str |

> 헷갈리는 이름: `numbers`·`nums`·`arr` → 보통 int / `s`·`word`·`id_list` → str

**단, 혼동하지 말 것**: dict는 **타입이 다른 키를 섞어 담을 수 있다.**

```python
pos = {1: (0,0), 0: (3,1), '*': (3,0), '#': (3,2)}   # ✅ 정상
pos['*']    # (3,0)   — 키를 찾을 때 서로 비교할 일이 없으니 문제없음
```

`1 != '1'`(값 비교)과 `{int키, str키 공존}`(키 조회)은 **다른 얘기**다.

### ④ 반복 중인 리스트를 건드리면 무한루프  [9/30 기사단원의 무기]

```python
for c in cnt_list:

        cnt_list2.append(power)
```

뒤에 계속 새 원소가 생기므로 반복이 끝나지 않는다. **에러도 안 나고 그냥 멈춘 것처럼 보인다.**

#### 1. `set` — 중복 제거

**언제**: "중복 없이 모아야 한다", "이미 나온 값인지 확인해야 한다"

```python
s = set()          # 빈 집합 ★ {}는 빈 dict이므로 주의
s.add(3)
s.add(3)           # 중복은 자동 무시 -> {3}
s.discard(3)       # 삭제 (없어도 에러 안 남)
3 in s             # O(1) ★ 리스트는 O(n)
len(s)             # 개수
```

- **순서가 없다.** 순서/정렬이 필요하면 마지막에 `sorted()`
- set에는 **불변값만** 넣을 수 있다 → 좌표는 튜플로: `s.add((x, y))` ✅ / `s.add([x, y])` ❌
- 집합 연산: `a & b`(교집합) `a | b`(합집합) `a - b`(차집합)

> **핵심 감각**: 리스트에 `in`을 쓰고 있으면 → set으로 바꿔라.
> 효율성 테스트 실패의 절반이 이걸로 해결된다.

#### 2. `sorted()` — 정렬된 **리스트**를 새로 만들기

**언제**: 오름차순으로 return해야 할 때 / set을 리스트로 바꿔야 할 때

```python
sorted({5, 3, 8})            # [3, 5, 8]  ← set을 넣어도 list가 나옴 ★
sorted(arr, reverse=True)    # 내림차순
sorted(arr, key=len)         # 기준을 정해서 정렬
arr.sort()                   # 원본을 직접 정렬 (반환값은 None!)
```

- `sorted()` = **새 리스트 반환** / `arr.sort()` = **원본 변경, 반환 없음**
- ⚠️ `arr = arr.sort()` 하면 `None`이 된다. 자주 하는 실수
- set + sorted 조합 = **"중복 제거 + 정렬"이 한 번에**

```python
return sorted(answer_set)    # set -> 정렬된 list. 반환 타입까지 해결 ✅
```

#### 3. `enumerate()` — 인덱스와 값을 동시에

**언제**: "몇 번째인지"와 "무엇인지"가 **둘 다** 필요할 때

```python
for i, x in enumerate(arr):          # i=인덱스, x=값
    ...

for rank, x in enumerate(arr, start=1):   # 1부터 세기
    ...

list(enumerate(['a','b']))           # [(0,'a'), (1,'b')]  ← 튜플을 만든다
```

- 값만 필요하면 `for x in arr` 를 쓴다. **인덱스를 안 쓸 거면 enumerate도 쓰지 않는다**
- 대표 용도: **값의 "위치"를 찾을 때**

```python
best = max(scores)
winners = [i for i, s in enumerate(scores) if s == best]   # 최고점자 인덱스 전부
```

- 2차원에서도: `for i, row in enumerate(board): for j, cell in enumerate(row):`

#### 4. `itertools.combinations` — 조합 뽑기

**언제**: "N개 중 M개를 뽑는 모든 경우" (순서 무관)

```python
from itertools import combinations, permutations, product

combinations([1,2,3], 2)     # (1,2) (1,3) (2,3)        조합 — 순서 무관
permutations([1,2,3], 2)     # (1,2)(1,3)(2,1)(2,3)...  순열 — 순서 중요
product([0,1], repeat=3)     # (0,0,0)(0,0,1)...        중복순열 — 각 칸에 선택지
```

- `combinations(arr, 2)` = 내가 손으로 짠 `for i: for j in range(i+1, n)` 과 **완전히 같은 것**
- 어떤 걸 쓸지 고르는 법:

| 상황 | 함수 |
|---|---|
| 순서 바꾸면 다른 경우 (123 ≠ 321) | `permutations` |
| 뽑기만 하면 됨 (123 = 321) | `combinations` |
| 각 자리에 여러 선택지, 중복 허용 | `product` |

> **주의**: 원리(이중 반복문)를 먼저 손으로 짜본 다음에 쓸 것.
> `combinations`만 외우면 변형 문제에서 막힌다.

#### 5. `dict` — 키로 값 찾기

**언제**: 번호·이름·좌표처럼 **의미 있는 키**로 값을 관리할 때

```python
d = {1: 0, 2: 0, 3: 0}       # {} 로 만든다 ★ []가 아님
d[1] += 1                    # 값 수정
d.values()                   # 값들만
d.items()                    # (키, 값) 쌍  <- 리스트의 enumerate에 해당

best = max(d.values())                          # ① 최고 '값'
winners = [k for k, v in d.items() if v == best]  # ② 그 값을 가진 '키' 전부
```

- ⚠️ **키는 불변값만** 가능. 리스트는 `TypeError: unhashable type: 'list'`
  → 좌표를 키로 쓸 땐 튜플로: `d[(x, y)]`
- ⚠️ `max(d)` = 최대 **키** / `max(d.values())` = 최대 **값**
- ⚠️ `max(d, key=d.get)` 은 **동점자 중 하나만** 반환 → 전원이 필요하면 위의 2단계 방식

**dict vs list 판단 기준**

| 상황 | 선택 |
|---|---|
| 키가 0,1,2… 연속된 정수 | 리스트 (인덱스가 곧 키) |
| 키가 1,2,3처럼 밀림 | dict (off-by-one이 사라짐) |
| 키가 문자열·좌표·띄엄띄엄한 수 | **dict** (리스트로는 불가) |
| 개수 세기 | `Counter` / `defaultdict(int)` |

> **중복이 정보일 때 set을 쓰면 안 된다.** 동점자를 찾아야 하는데 set에 담으면
> 점수가 합쳐져서 "누가 몇 명인지"가 사라진다. (모의고사에서 실제로 겪음)

#### 6. `max` / `min` — 최댓값은 정렬하지 말고 바로

```python
max(arr), min(arr)                 # O(n)
sorted(arr)[-1]                    # O(n log n) — 최댓값만 필요하면 낭비
max(a, b), min(a, b)               # 값 두 개 비교
max(arr, key=len)                  # 기준을 정해서
max(d.values())                    # dict의 최대 '값'
```

**"각 원소 안에서 나눈 뒤, 그룹별 최댓값"** 패턴 (최소직사각형):

```python
max(max(w, h) for w, h in pairs)   # 각 쌍의 큰 값들 중 최댓값
max(min(w, h) for w, h in pairs)   # 각 쌍의 작은 값들 중 최댓값
```

> 정렬은 **순서 전체**가 필요할 때만. 최댓값 하나면 `max()`가 빠르고 의도도 명확하다.

#### 7. 언패킹 — 인덱스 대신 이름으로

```python
for w, h in sizes:        # ✅ w, h 가 뭔지 바로 읽힘
for size in sizes:        # ❌ size[0]이 뭐였는지 되짚어야 함
    size[0], size[1]

for i, x in enumerate(arr)       # (인덱스, 값)
for k, v in d.items()            # (키, 값)
for a, b in combinations(arr, 2) # (원소1, 원소2)
```

중첩 리스트 `[[60,50], [30,70]]` 는 `for w, h in ...` 로 바로 풀린다.

#### 8. 컴프리헨션 (덤)

```python
[x*2 for x in arr]              # 리스트
{x*2 for x in arr}              # set    ← 괄호만 바꾸면 됨
```

#### 6. 격자 좌표 매핑 — "위치"를 dict로

**언제**: 키패드·보드·판처럼 **칸마다 자리가 정해진 것**에서 거리·이동을 다뤄야 할 때

```python
pos = {}
for n in range(1, 10):
    pos[n] = ((n - 1) // 3, (n - 1) % 3)   # 1~9 -> (행, 열)
pos[0] = (3, 1); pos['*'] = (3, 0); pos['#'] = (3, 2)
```

`//`는 **몇 번째 줄**, `%`는 **줄 안에서 몇 번째**. 격자를 1차원 번호로 다룰 때의 기본 공식.

> ★ **숫자 자체로는 거리를 못 잰다. 좌표로 바꿔야 잴 수 있다.** 이게 이 문제의 핵심이었다.

#### 7. 맨해튼 거리 — 상하좌우로만 갈 때의 거리

```python
def dist(a, b):
    (x1, y1), (x2, y2) = pos[a], pos[b]
    return abs(x1 - x2) + abs(y1 - y2)
```

대각선으로 못 가므로 **세로 차이 + 가로 차이**. BFS/DFS(3단계)에서 계속 나온다.

#### 8. 여러 값 중 하나인지 — `in` + 튜플

```python
if number in (1, 4, 7):      # ✅
if number == 1 or number == 4 or number == 7:   # 같은 뜻, 길다
```

⚠️ 따옴표 주의 → 🔴 반복 실수 ③

#### 9. 그리디 — "처리된 범위"를 변수로 들고 다니기 ★ 패턴

```python
cnt = 0
end = 0                  # 지금까지 덮인 마지막 지점
for s in section:
    if s > end:          # 아직 안 덮였다
        cnt += 1
        end = s + m - 1  # ★ end가 아니라 s 기준
return cnt
```

**핵심**: `section[i-1]`(직전 **원소**)과 `end`(직전 **롤러가 덮은 끝**)는 **다른 값**이다.
이걸 헷갈려서 두 번 틀렸다.

> 같은 구조가 나오는 문제: **기능개발 / 구명보트 / 단속카메라** (10/5, 10/16)

#### 10. 올림 나눗셈 — `math.ceil` 대신 정수 연산

```python
-(-a // b)          # a/b 올림
(a + b - 1) // b    # 같은 뜻
math.ceil(a / b)    # ⚠️ 실수를 거쳐서 큰 수에서 오차
```

`//`는 **버림**. 음수에서는 더 작은 쪽으로 내려가므로, 부호를 두 번 뒤집으면 올림이 된다.

#### 11. 중첩 언패킹

```python
(x1, y1), (x2, y2) = pos[a], pos[b]     # 튜플 2개를 한 줄에 풀기
```

#### 12. 첫 원소 특별대우는 초기값으로 없앤다

```python
cnt = 1; end = section[0] + m - 1   # △ 동작은 하지만 빈 리스트에서 IndexError
cnt = 0; end = 0                    # ✅ 예외 없음
```

> **"첫 번째만 따로 처리"가 필요해 보이면 초기값을 의심한다.** 예외가 줄면 버그도 준다.

#### 13. 약수 개수 세기 — **√n 까지만** ★★ 공식

```python
cnt = 0
j = 1
while j * j <= i:            # √i 까지만 (math.sqrt는 실수 오차 → 쓰지 말 것)
    if i % j == 0:
        cnt += 1 if j * j == i else 2   # 짝이 자기 자신이면 1개, 아니면 j와 i//j 2개
    j += 1
```

**약수는 항상 짝으로 나온다.** `1`을 찾으면 `36`도 같이 알게 된다.

```
36 = 1×36 = 2×18 = 3×12 = 4×9 = 6×6   ← √36=6 에서 끝
6번만 돌고 약수 9개를 전부 찾음
```

| n=100,000 | 반복 횟수 |
|---|---|
| 1부터 i까지 전부 | 약 50억 ❌ |
| √i 까지만 | 약 2천만 ✅ |

> ★ **소수 판정도 똑같다.** "n이 소수인가?"도 √n까지만 확인하면 된다.

#### 14. `itertools` ↔ for문 대응표

| itertools | for문 | 언제 |
|---|---|---|
| `combinations(arr, 2)` | `i`, `j = i+1` | 순서 무관, 중복 없이 2개 |
| `combinations(arr, 3)` | `i`, `j = i+1`, `k = j+1` | 3개 |
| `permutations(arr, 2)` | `i`, `j` 둘 다 전체 + `if i != j` | **순서 중요** |
| `product(arr, repeat=2)` | `i`, `j` 둘 다 전체 | 중복 허용 |

```python
for i in range(n):
    for j in range(i+1, n):          # ★ i+1 이 중복·자기자신을 동시에 막는다
        for k in range(j+1, n):
            ...
```

**`combinations`를 쓰되 for문 버전도 칠 줄 알아야 한다.**
- 고르는 도중에 조건으로 가지치기해야 하면 for문이어야 한다 (→ 백트래킹)
- for문으로 보면 **O(N³)이 눈에 보인다.** `combinations` 한 줄은 복잡도가 안 보여 시간 초과를 놓치기 쉽다

#### 15. 내장 함수 이름을 변수로 쓰지 말 것

```python
dir = {...}     # ⚠️ dir()는 내장 함수
sum = 0         # ⚠️ 이후 sum() 사용 불가 — 아주 흔한 사고
```
`list, dict, str, sum, max, min, id, input, type` 등.

#### 16. 에러 메시지 읽는 법

**맨 아랫줄 + 줄 번호**만 보면 된다. 위의 긴 경로는 무시.

| 메시지 | 뜻 |
|---|---|
| `'int' object is not iterable` | `for i in h:` — 정수를 목록처럼 씀 |
| `object of type 'int' has no len()` | `len(cnt)` — 정수에 `len()` |
| `'int' object is not subscriptable` | `park[nx[ny]]` — 정수에 `[]` |

> **`'int' object is ...` → "정수한테 목록 취급했구나"** 로 바로 번역할 것.
