## 4. ★ 나만의 무기 — 이 레포

**25일간의 코딩테스트 준비 기록 전체가 면접 재료다.** 다른 지원자는 이걸 못 가져온다.

| 자산 | 숫자 | 면접에서 쓰는 법 |
|---|---|---|
| 오답노트 | `04-review-log.md` · **도구 62개** | "같은 실수를 2번 하면 기록하는 규칙을 만들었습니다" |
| 치트시트 | `05-exam-final-check.md` · **졸업(삭제) 규칙** | "항목이 쌓이기만 하면 못 봅니다. **3일 연속 무사하면 지웁니다**" |
| 푼 문제 | **29문제** (BFS/DFS 8 · 구현 10 · DP 4 · 완전탐색 6 · 그리디 1) | 유형별 분류 = 체계적 접근 |
| 공백 대응 | 13일 공백 후 **5일 플랜으로 재설계** | "남은 시간에 맞춰 **버릴 것을 먼저 정했습니다**" |

### 💡 이 경험을 한 문장으로

> **"무엇을 버릴지 먼저 정하고, 틀린 것은 반드시 기록하고, 잘하게 된 것은 지웁니다."**

→ 이건 **IT 운영/개발 업무의 태도 그 자체**다. 자기소개·장점·학습방법 질문에 전부 연결된다.

### ⚠️ 위험 질문 대비 — "코딩테스트 3문제 중 1문제만 푸셨네요?"

**절대 변명하지 않는다.** 사실 + 원인 분석 + 그 후의 행동, 3단으로 짧게.

```
사실:   네, 알고리즘 3문제 중 1문제, SQL은 2문제 모두 풀었습니다.
원인:   마지막 문제에서 순열을 쓰는 방식 자체는 맞았는데
        구현 단계에서 시간을 다 썼습니다.
행동:   시험 직후 그 부분을 다시 확인해서 오답노트에 남겼습니다.
        (62번째 항목입니다)
마무리:  준비 기간이 25일이었고 그 안에서 BFS/DFS와 DP를 새로 익혔습니다.
        지금은 그때보다 분명히 빠릅니다.
```

> **핵심은 "기록하고 고쳤다"는 증거가 실제로 있다는 것.** 이 레포를 말로 설명할 수 있어야 한다.

## 5. 집단면접 — 반드시 준비할 답변

> 소리 내어 말해보고 **시간을 잰다.** 머릿속으로만 하면 실전에서 3배 길어진다.

### 필수 5개 (이것만은 외운다)

| | 질문 | 분량 |
|---|---|---|
| 1 | **1분 자기소개** | **40~50초** (1분이라고 하면 1분을 넘긴다) |
| 2 | **지원동기 — 왜 농협중앙회인가** | 40초 |
| 3 | **왜 IT 직군인가 / 왜 다른 회사 아닌 여기인가** | 40초 |
| 4 | **입사 후 포부 (3년 / 10년)** | 40초 |
| 5 | **본인의 단점** | 30초 |

> ⚠️ **2번과 3번이 가장 많이 묻고 가장 많이 망하는 질문이다.**
> "농협이 좋아서"는 답이 아니다. **"농협중앙회 IT가 하는 일 중 ○○에 기여하고 싶다"**까지 가야 한다.
> → 그러려면 §7의 회사 조사가 선행되어야 한다.

### 추가 예상질문 (답변 키워드만 메모해 두기)

- 갈등을 겪고 해결한 경험 / 팀에서 맡았던 역할
- 실패한 경험과 거기서 배운 것 ← **코테 준비 13일 공백 → 재설계** 스토리 사용 가능
- 가장 열정적으로 한 일
- 농협에 대해 아는 것 / 최근 본 농협 뉴스
- 비전공자라면: **왜 IT로 전환했는가** (반드시 나온다)
- 다른 곳도 지원했는가 / 떨어지면 어떻게 할 것인가
- 마지막 하고 싶은 말 ← **반드시 준비.** 비워두면 손해다

> 📌 **모든 답변은 "결론 → 근거/경험 → 그래서 입사 후"** 3단으로. 경험은 **숫자**를 넣는다.

## 6. PT면접 — 구조가 내용보다 중요하다

5분 발표에서 심사하는 것은 **지식이 아니라 "논리적으로 구조화해서 전달하는가"**다.
주제를 몰라도 **틀이 있으면 평균은 한다. 틀이 없으면 아는 주제도 망한다.**

### ★ 외울 PT 템플릿 (5분 = 약 5단락)

```
[0] 도입  (20초)  "○○에 대해 발표하겠습니다. 결론부터 말씀드리면 △△입니다."
                  → ★ 결론을 맨 앞에 던진다. 끝에 두면 시간 초과로 못 말한다.

[1] 현황  (50초)  자료에서 읽은 사실 2~3개. 숫자를 그대로 인용한다.
                  "자료 2번을 보면 ~가 전년 대비 ○% 증가했습니다."

[2] 문제  (50초)  그래서 무엇이 문제인가. 원인 2가지로 쪼갠다.

[3] 방안  (120초) ★ 여기가 본론. 반드시 3개. 단기 / 중기 / 장기 로 나누면 편하다.
                  각 방안마다  "무엇을 - 어떻게 - 기대효과"

[4] 마무리 (40초) 방안 3개를 한 문장으로 다시 묶고,
                  "농협중앙회 IT 직원으로서 ○○에 기여하겠습니다."
```

> **"3개로 나눈다"가 전부다.** 원인 2개, 방안 3개. 숫자를 미리 정해두면 말이 끊기지 않는다.

### 준비시간(10~20분)에 하는 순서

```
1. (2분)  자료 전체 훑고 숫자에 동그라미
2. (3분)  결론 한 문장 먼저 쓴다  ← ★ 이걸 먼저 안 쓰면 끝까지 안 나온다
3. (5분)  방안 3개 제목만 쓴다
4. (나머지) 각 방안에 근거 1개씩 붙인다
5. 남은 1분: 도입 문장 소리 내서 한 번
```

> 코테의 **"설계를 주석으로 먼저 쓴다"**와 똑같은 원리다. 결론을 먼저 적는 것이 설계다.

### 예상 주제 (IT 5급 — 📌 예측이며 확정 아님)

| 분류 | 주제 |
|---|---|
| 디지털 전환 | 농협 디지털 금융 서비스 개선 방안 · 비대면 채널 확대 |
| 데이터/AI | 농업 데이터 활용 방안 · AI 기반 금융 서비스 |
| 스마트농업 | 스마트팜 확산 방안 · 농업 ICT |
| 포용 | **고령 농업인의 디지털 소외 해소** ← 농협다운 주제. 1순위로 준비 |
| 보안 | 금융 보안 강화 / 개인정보 보호 |
| 찬반형 | 특정 제도 도입 찬반 (과거 리디노미네이션 사례) |

> 💡 **어떤 주제가 나와도 마지막은 "농업인·조합원에게 어떤 도움이 되는가"로 닫는다.**
> 농협은 일반 기업이 아니라 **협동조합**이다. 수익성만 말하면 감점 요인이다.

## 7. 토론면접 — 이기려 하면 떨어진다

**12명 이내를 2팀으로 나눈 찬반 토론, 약 40분.** 채점자가 옆에서 기록한다.

### 점수가 올라가는 행동

| | 행동 |
|---|---|
| ✅ | **초반 2분 안에 한 번은 말한다.** 늦을수록 들어가기 어려워진다 |
| ✅ | **상대 주장을 먼저 요약하고 반박한다** — "○○님 말씀처럼 ~한 측면은 동의합니다. 다만" |
| ✅ | 침묵이 생기면 **쟁점을 정리한다** — "지금까지 나온 쟁점은 비용과 실효성 두 가지인 것 같습니다" ← **가장 높은 점수** |
| ✅ | **발언 안 한 사람에게 기회를 넘긴다** — "○○님은 어떻게 보시나요?" |
| ✅ | 숫자·사례를 1개라도 든다 |

### 감점 행동

| | 행동 |
|---|---|
| ❌ | 말 끊기 / 목소리 키우기 |
| ❌ | 한 번도 발언 안 함 ← **가장 치명적** |
| ❌ | 혼자 길게 말하기 (1회 발언 **40초 이내**) |
| ❌ | 상대 인신공격, 비꼬기 |
| ❌ | 결론 없이 흐지부지 — **끝나기 5분 전 "정리하면" 한 번** |

### 준비 방법 (11/13)

주제 5개를 정해 **찬·반 양쪽 논거를 각 3개씩** 써 본다. 어느 팀이 될지 못 고르기 때문이다.

> 추천 주제: 농업 분야 AI 도입 · 농산물 유통 플랫폼 직거래 확대 · 금융권 망분리 규제 완화 ·
> 디지털 전환 속 점포 축소 · 기본소득/농민수당
